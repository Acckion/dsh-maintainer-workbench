## 按顺序录制

### 1. 开始录屏，展示仓库与 PR

用自己熟悉的工具录制 Harness 窗口。macOS 自带工具可用 ⌘⇧5，选“录制所选部分”，框住 App 的演示内容区。麦克风选“无”；不必录系统声音。片头和配音后期统一制作。

Mac 会自动锁屏，录制前由你解锁。最后已核对 PR #13 的 Diff 页面能正常显示三个文件；如果解锁后仍停在这里，可以先点击 Summary 再按下面拍。模型等待期间保持电脑醒着，偶尔轻移鼠标即可。

开始后先补一段列表素材：点 Issues，显示数量与几条新标题，停 5–8 秒；再点 Pull Requests，显示新增贡献与草稿，停 5–8 秒。全部条目都是自建演示数据，不需逐一运行。随后继续：

1. 让仓库名 `LovelyFlash/dsh-acceptance-suite` 清楚可见，停 5 秒。
2. 保持在 Pull Requests 页，选中 `#13 · core: 新增 average / median 统计函数`，停 8 秒。列表变长后可在搜索框输入标题中的 `average` 定位；准备好后再清除搜索以补拍全列表。
3. 点右侧的 **Summary**，让 PR 内容可辨认，缓慢滚动一次；停 5–8 秒。素材中保留其验收样例身份。
4. 点 **Diff**，让三个变更文件和主要差异可见，缓慢滚动，合计留 15–20 秒。
5. 回到 **处理流程**。不要去旧的 README-only 本地案例，也不打开其他仓库。

这段回答：正在审查哪份贡献，改了什么。点击和滚动后各停 2–3 秒即可，不必追求一次完美。

### 2. 录下“开始预检”

1. 在阶段条选择 **预检**；界面应显示“待开始”和 **开始预检**。
2. 展开 **补充本次要求**。若已填好，缓慢展示；若为空，粘贴下文。填完停 5 秒。
3. 将鼠标移到 **开始预检**，停 3 秒，再点击一次。
4. 保持录屏，等当前阶段实际结束。等待时间不用自己处理。
5. 结果出现后停 8 秒，录清版本、变更范围和检查状态。已有 GitHub 检查与本次预检结论分别呈现。

补充要求：

```text
本次为自建验收仓库视频演示。仅对当前 PR 做只读检查，核对变更范围、版本和检查状态；审查时核对实际行为、测试与文档是否一致。结论引用实际读取的源码或工具证据，说明触发条件、影响、路径与行号；覆盖不足如实标明。不要修改文件、发布评论、应用标签、创建或合并 PR。已有充分依据后完成当前阶段报告，避免反复读取相同内容。
```

### 3. 录下真正的变更审查

1. 预检完成后，点阶段条中的 **变更审查**。
2. 在该阶段的“补充本次要求”核对上述要求。不同阶段可能各自保存要求，若为空就再次粘贴。
3. 点击该阶段给出的开始按钮，始终保留启动前、启动后和最终状态的录像。
4. 执行期间不用追着滚动。若能打开当前任务或 Harness 会话，选一段实际读取源码、查看差异或运行命令的记录，停 10–15 秒，再回到工作台。
5. 结束后让状态和摘要清楚可见，停 8 秒。发生补充输入、环境阻塞、超时或其他失败时，录清实际原因后把状态告诉我；不要用另一次旧任务接续本轮结果。

这段回答：AI 实际做了什么，留下了什么可供核对的材料。不是要求它一定找出预先列出的全部问题。

### 4. 展示一条有证据的发现

1. 打开本轮审查结果。若进入任务详情，使用 **概览 / 执行记录 / 审阅与证据**。
2. 从本轮实际报告中选择一条容易解释、证据充分的问题；若报告确实指出平均值计算错误，优先展示这一条。
3. 先停在问题描述 8 秒，再展示对应文件位置、触发条件和实际证据 10–15 秒。
4. 再展示测试覆盖或文档问题中一条确有依据的发现，留 10 秒左右即可；其余我在后期筛选。
5. 查看风险与未覆盖范围，停 5 秒。

如果模型没有给出可核对的发现，或者报告尚未通过证据门槛，就录实际状态，不手工补成模型发现。准备阶段的独立复现可以另作来源明确的图卡。

### 5. 录下维护者判断

在“维护者确认”或审查结果的逐项处置处，核对证据再作真实决定。可见选项以当前界面为准，常见为“接受，交给实施”“需要更多证据”“驳回”。

1. 让一条发现及其处置选项清楚可见，停 3 秒。
2. 选择实际判断。证据充分才接受，证据不足就请求更多证据。
3. 如果有处置理由，写一句具体理由，例如“触发输入与当前源码对应，记录此问题，交由后续修订”。
4. 保存后停 8 秒，展示这条发现的实际处置状态。

如整个报告具备接受条件，可填写审核备注后点 **接受此报告**；这是本地接收报告，不等于认可 PR 正确或批准合并。此次计划是审查，不需要为了结尾继续做代码修复。

### 6. 导出本轮结果，结束录屏

在本轮任务详情的操作区找到 **导出结果**，导出实际报告文件，保留下载结果。审查任务通常没有修改补丁，不以“下载补丁”作为必拍步骤。

回到本轮结果页面，最后停 8 秒，再停止录屏。这个主线先以本地报告交付结束；如果后续另拍真实 GitHub 评论或新 PR，另写明确镜头并保留真实回执，不把预览当发布成功。
