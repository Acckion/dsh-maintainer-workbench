## 1. 成片目标与固定边界

让第一次了解项目的评委看懂一个过程：维护者面对一条具体问题，确认修改目标；AI 调查和执行；工作台归集当前修改的证据；维护者据此接受或退回，并明确交付状态。视频不能把所有时间用于展示界面菜单，也不以模型响应速度或一次成功推出整体效率。

本次只使用一个自建分账样例：总额 10 元、3 位参与者。预设错误是每人 333 分，合计 999 分；预期按固定参与者顺序分为 334、333、333 分，合计 1000 分。该原型是**被维护的演示仓库**，不是工作台新增的记账或支付功能。

固定边界如下：

- 主线运行统一使用同一个 Harness 原生隔离 profile、同一演示仓库及已登记的任务上下文。默认不切换到独立预览充当原生运行画面。
- 主线交付采用本地补丁导出。默认没有 GitHub 评论、标签、分支推送、草稿 PR、合并或其他远端写入。
- 全程持续显示“自建样例·预设缺陷”。即使后续采用真实模型，仍属于在预设缺陷上的实际执行，不变成未经设计的真实社区事件。
- 模型来源单独标明：实际远端模型、本地模型、脚本模型或尚未执行。脚本回复、合成 UI、设计示意和历史回放分别标清，不能只在片头一闪而过。
- 只按真实发生的阶段讲述。不会人为增加模型失误、审批、中断或先失败后通过的剧情。预设回归测试的失败可以展示，但必须说明它来自案例基线。
- 没有合格补丁时，展示失败、阻塞、退回或未交付的实际状态；不用手工准备的正确答案冒充本次 AI 产物。

参赛要求为：原则上须提交演示视频；格式为 MP4，时长 3–5 分钟，不超过 300MB。本次编辑目标为 240 秒。正式材料不得出现学校名称、学校标志或指导教师信息。规则与其他材料入口见[参赛准备状态](../product/COMPETITION-READINESS.md)。

## 3. 自建分账案例与验收条件

案例资料集中保存在 [case/](../../artifacts/video-preparation/case/)。问题描述、原型和测试必须共同说明以下规则，避免在执行过程中临时改变答案：

| 内容 | 固定约定 | 需要保留的证据 |
|---|---|---|
| 金额与顺序 | 以整数分计算，样例总额 1000 分，参与者为固定输入顺序的 3 人 | 输入、原型画面、案例说明 |
| 已知错误 | 向下取整后得到 `[333,333,333]`，总和 999 分 | 未修复基线的实际输出与测试日志 |
| 样例预期 | 余数按固定顺序分配，结果为 `[334,333,333]` | 独立于模型自述的验收断言 |
| 总额守恒 | 分配之和等于原总额 | 回归测试的具体断言及实际结果 |
| 差额约束 | 该样例任意两人的金额最多相差 1 分 | 回归测试与结果画面 |
| 修改边界 | 本例只允许修改 `split-bill.cjs`；现有验收测试、接口和输入校验保持原样，不新增依赖、不访问网络 | 工作台已确认目标、实际 diff 与范围检查 |
| 未验证范围 | 不据单例保证税费、多币种、退款、支付系统或所有金额输入正确 | 审阅摘要、片尾局限与原始记录 |

如果增加其他输入测试，先将预期规则写入案例资料，再执行并记录，不能为了让当前补丁通过而修改验收标准。界面用“10 元”和“差 1 分”解释问题，技术证据可保留 1000、999 等整数分值。

演示仓库独立于工作台产品源码。后续 AI 或人工修改只能进入明确授权的演示范围，不为录屏修改工作台产品代码，也不将既有用户改动混入演示补丁。

## 4. 角色与实际执行顺序

角色是制作职责，不是虚构用户。人数有限时可以兼任，但必须如实登记；正式视频不展示不必要的个人身份。独立验收由未参与该次实施的人完成更有说服力，无法安排时明确说明局限。

| 角色 | 主要任务 |
|---|---|
| 案例准备者 | 保存基线、预设缺陷、允许范围与预先确定的验收条件 |
| 操作者/维护者 | 在同一原生 profile 中确认目标、启动、查看证据并作出接受或退回决定 |
| 证据记录者 | 登记版本、会话与任务关联、命令输出、原始录像及剪辑出处，检查秘密信息 |
| 人工验收者 | 核对验收条件、实际产物、测试覆盖与未完成项，不只复述模型报告 |
| 配音与后期制作者 | 按实际结果选择配音分支，标注加速、删减等待、回放与素材性质 |

建议按下列顺序执行，先把任务真实走完，再决定剪辑取舍：

1. **固定素材基线。** 确认案例文件及基线，保存预设问题与失败回归；登记工作台版本、宿主、隔离 profile 标识和演示仓库提交。
2. **核对运行条件。** 使用实际支持的本地仓库或工作区维护入口打开案例，确认已有目标与允许范围。模型、数据和费用条件未明确时，先停留在准备阶段；不自动调用或借用日常环境。
3. **完成一次连续原始记录。** 从问题与目标确认开始，记录真实调查、执行、验证、审查和最终判断。保存完整过程与等待，不为追求四分钟在运行时删去异常。
4. **保存产物与依据。** 将报告、差异、工具输出和导出结果关联到同一个任务和补丁。若未成功，则保存实际失败原因及未交付状态。
5. **人工核对结果。** 逐条检查总额、分配差额和修改范围，记录接受、退回或尚不能决定的原因。
6. **补录说明镜头。** 可以补录片头、已保存结果的查看和片尾资源说明，但注明“结果回看”，不把补录重新排列成伪造的执行顺序。
7. **选择配音分支并剪辑。** 只使用与本次事实一致的通过或未通过分支；准备完成后核对字幕、证据出处和最终技术规格。

如果需要重跑，保留前一次记录并登记原因；新的尝试使用新的运行标识。重跑不覆盖失败样本，也不把多个运行的优点合并成一次看似连续的成功。

| S4 / 105–155 秒 | 当前版本、实际 diff、一次真实工具测试、未验证范围 | 本次补丁、命令/退出码/输出、报告和对应会话记录 | 模型自报与真实工具输出分开；不能展示旧补丁的测试作为本次证明 |
| S5 / 155–190 秒 | 人依据结果接受或退回，默认只导出本地补丁 | 实际审阅决定、可交付补丁及导出文件，或失败/阻塞记录 | 导出不等于 GitHub 已发布；无合格补丁明确“未交付” |
| S6 / 190–220 秒 | 对总额、差额和范围逐项验收，按实际结果选择互斥配音 | 人工验收表、独立于模型自述的核对依据 | “通过”与“未通过”分支只能选符合事实的一支；不展示效率/成功率百分比 |
| S7 / 220–240 秒 | 源码、安装、资源与案例复现入口，以及单样例局限 | 已核对的有效访问方式或本地待交付状态、资源清单与 AI 辅助说明 | 链接未公开就不声称已开放；说明本例不能代表真实社区总体效果 |

每段至少保存一条素材定位记录：原始文件、开始/结束时间、任务或证据编号及素材性质。优先录清楚“问题、依据和决定”，不必把所有技术日志塞进画面。必要时给真实记录加局部放大或旁注，旁注不得遮住错误、未完成项或改变原始含义。

脚本另列的故障注入属于可选备份，本次默认不加入主线。如最终采用，只能等时替换 S4 内镜头，并持续标“另一个合成场景·故障注入”；单独登记输入与结果，不将其接到分账任务中充当同一次模型经历，也不增加 240 秒总长。

登记表应能回答以下问题；可使用现有字段或对应内容，无须为本计划另建冲突的登记格式：

- **它是什么？** 文稿、预设案例、准备检查、实际工具记录、原生屏幕录制、脚本模型回放、合成 UI 或设计示意。
- **它来自哪次运行？** 日期、时区、工作台 HEAD 与工作树状态、构建/包标识、宿主版本、隔离 profile 标识、演示仓库提交、任务与会话关联。
- **模型真的参与了吗？** 提供方、模型标识、推理配置、真实/本地/脚本性质、实际调用证据；未运行写未执行，不以未知代填 0 次或 0 元。
- **它证明什么？** 对应验收条件、实际命令、退出码、产物和限制；失败也照实记录。预期失败的基线日志不能作为修复后通过的证据。
- **它如何进入成片？** 镜头编号、原始文件时间范围、剪辑是否加速/省略等待/补录、字幕标签与配音分支。
- **它能否展示？** 自建/改编来源、许可或展示授权、AI 辅助说明、脱敏处理、复核人及待处理事项。

登记只使用必要的匿名标识。凭据、认证链接和不必要的私人绝对路径不进入可分享登记表；需要追溯的敏感原始记录单独受限保管。公开副本的遮挡和脱敏应留说明，不修改测试结果或隐去失败事实。

已有历史证据可用于解释机制或制作准备，不冒充本次实际运行。确需引用历史截图时，在画面标出历史日期及“合成数据/历史环境”等限制，并登记出处；主线 S3–S6 优先使用同一次当前原生运行的材料。其他证据类型见[证据索引](EVIDENCE-INDEX.md)。

## 7. 配音、字幕与剪辑

**配音先匹配结果，再压缩表达。** 依脚本先录正常语速版本；实际出现阻塞、修改不完整或未交付时，采用对应分支，不说“已经修复”“可以交付”。没有真实模型运行时，可以制作片头、目标和准备说明，但不能为尚未发生的运行预录肯定结果。

**主线名称保持一致。** 用“问题反馈、修改范围、实际核验、维护者决定”解释必要概念，首次出现时简短解释 Issue、PR 或补丁。重点落在 10 元为什么少 1 分、怎样核对本次修改，以及人凭什么接受，不把视频变成日志朗读。

**字幕可以按以下制作约定执行：** 1080p 成片默认每屏最多两行，每行约 18–22 个汉字，正文字幕建议至少 26 像素并做实际可读性检查。字幕不遮住关键状态、实际金额、退出结果或接受/退回按钮。配音字幕与角落的来源标签分开，来源标签在对应场景持续可见。

**保留原始时间关系。** 可把真实等待加速或省略，但注明“加速”或“等待已省略”；成片时长不作为任务耗时。结果回看、不同尝试和历史材料有清楚转场。不得用手工编辑的状态、合成页面、其他任务的通过日志或事后修好的原型替换本次结果。

**素材与声音来源可核查。** 使用团队实际录制且有权展示的配音；如用语音合成，应登记服务、音色许可、适用条款与 AI 辅助。默认不依赖背景音乐；使用音乐、字体或额外图像时补充来源与授权。正式评审版检查桌面、浏览器、通知、文件路径和字幕中的学校及指导教师信息。

建议以 1920×1080、30fps 录制，最终采用 MP4/H.264 视频与 AAC 音频；视频码率可先用 6–7Mbps、音频 128–160kbps，再按实际清晰度和体积调整。这些是制作建议，不是赛事额外硬性标准。原始录像可以高质量保存，不能为减小文件而使 1 分差额、测试结果和来源标签无法辨认。

导出后记录实际分辨率、帧率、时长、音视频编码、文件字节数与校验值；检查开头、结尾、每段切换及关键证据镜头，并完整播放确认。需要进一步压缩时保留原版，重新导出后重新检查，不沿用前一个文件的大小与验收记录。

只有当实际文件完成这些检查、团队确认展示权利与评审访问安排后，才能标记“可提交视频”。成片检查不代替产品最终包验收、报名状态核实或平台提交回执。
