# PR 审查后的验证交接

## 目标与实施顺序

1. 统一判定审查报告中尚未解决、阻塞 validate 的验收缺口，区分源码审查通过与事项验收完成。
2. 已确认的 PR 审查流程自动交接必要验证；没有验证缺口时不增加任务。缺陷处置和范围变更仍由维护者决定。
3. 验证绑定来源审查、当前 PR 身份及版本。成功且未改代码时复用原审查，直接最终审核；失败、环境阻塞、取消和旧版本不得继续。
4. 时间线与主动作显示验证和恢复进度，最终接受受同一证据规则约束；补查和人工步骤沿用 master 的统一工作流入口，不恢复已移除的独立执行入口。
5. 验证环境恢复在版本与补丁不变、目录所有权可恢复时复用原工作区，保留已准备的依赖，使用新会话重新采集证据；代码变动则拒绝恢复。环境阻塞沿用现有等待与恢复机制，清晰展示验证工作区和所需条件。仓库克隆不等于运行时、包管理器及依赖准备；本次不擅自新增全局安装或执行仓库安装脚本。

## 验证

覆盖自动交接、重复完成事件、成功后无循环、失败与环境恢复、版本变化、缺陷处置、无须验证以及最终接受门禁；保持既有 Issue 修改→验证→审查路线。
