# 验证工作区的环境准备

## 目标与顺序

1. 沿用仓库设置，增加显式环境策略：默认手动；可自动准备锁定依赖，单独控制网络、生命周期脚本、根项目/工作区范围及工具目录。
2. 后端在应用补丁后、启动验证模型前检查 Node engines、包管理器版本、锁文件和本目录依赖。只在受管理且已取得所有权的工作区执行固定安装命令，不交给模型猜命令。
3. 就绪记录绑定工作区、HEAD、补丁、清单、锁文件、运行时和策略；记录不是测试证据。重复执行先复查依赖；准备成功继续当前任务；失败不自动循环。不同目录只共享下载缓存。
4. 保存准备进度、日志和失败原因，支持取消、超时、重启与明确重试。安装后核对 HEAD、补丁及清单未变，发生变化则停止。
5. 克隆就绪不再批量解除仓库中全部环境等待。界面展示环境准备阶段、授权和日志，区分系统工作与维护者决定。
6. 本事项明确禁止安装时，自动策略不能覆盖；维护者可明确授权当前周期、当前版本及补丁的环境准备。授权沿明确来源链传递，代码、周期或策略变化即失效；验证 Agent 仍禁止安装。
7. 独立审查目录不必重复安装已验证补丁的依赖。明确来源链上的同版本同补丁验证如已逐项完成所需命令，可复用其真实证据；新增检查和更晚的失败记录不能被前序通过掩盖。界面使用派生状态展示覆盖，原始报告保持不变。

## 初期支持与边界

- npm/package-lock、pnpm/pnpm-lock，固定版本且 frozen 安装；不修改锁文件、不全局安装运行时或包管理器，不执行 pnpmfile。
- 自动准备默认关闭，联网及安装脚本默认关闭。缺少锁文件、工具版本不匹配、不支持的包管理器或策略不足时明确等待。
- 每仓库串行安装，进程可中断；验证测试继续在新会话实际运行，不沿用环境准备日志冒充通过。
- 覆盖权限、缺工具、版本不符、重复准备、依赖删除、锁文件变化、工作区越界、安装失败/取消、安装修改代码、恢复及自动进入验证的回归用例。
