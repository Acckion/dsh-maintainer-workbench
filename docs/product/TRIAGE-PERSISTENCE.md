# 分诊缓存与自动化（0.1.3）

分诊是元数据路由，代码调查、修复和审查继续作为独立阶段。默认跟随 Harness 模型，不创建代码 worktree、不开放工具。

## 持久化与失效

SQLite WAL 保存仓库、事项、任务、设置和独立 triage_cache。缓存主键为事项 ID 与输入版本（updatedAt、正文、标题、状态等）；普通仓库提交不会让 Issue 分诊失效。结果、任务完成状态、事项当前分析在同一事务中提交。旧安装的 completed 分诊任务会幂等回填缓存，不清理历史记录。任务索引按事项、阶段、版本查找，重复点击复用已完成或在途任务。

同步从版本缓存恢复结果，不调用模型。事项版本变化后重新派发；旧版本仍可在任务记录中查看。评论编辑通过 GitHub updatedAt 失效，不仅依赖评论数量。进程中断任务标记失败，禁止自动重新执行，允许人工重试。

## 自动分诊

设置默认关闭。启用后，手动或定时同步触发新增/变化的开放 Issue；PR、仓库整理事项、已关闭项不参与。后台每分钟补齐积压项，即使定时同步关闭也能补齐已同步事项。全局排队/运行的分诊数量受每批上限约束，并发沿用执行设置。失败和取消的同版本不会自动重试，避免循环计费。关闭后不再派发，已派发任务需在执行页取消。工作区发现本身不会触发 Agent。

## 输入与预算

不传 analysis、workflow、历史 handoff 或 GitHub user 对象。正文最多 6000 字符、重复候选最多 6 项且正文各 500 字符、评论最多 5 项且每项 800 字符。讨论 API 仅在有评论时读取，当前取第一页最多 30 条中的末 5 条，明确披露较新讨论可能缺失。不截断 JSON 结构。缺失或裁剪范围以 coverage 元数据提供。

分诊输出默认最多 1800 token，可在高级设置调整至 500–8000，最终也受通用/仓库上限限制。模型应仅输出少量证据、步骤和回复草稿；不强制降低宿主推理等级。预算是上限，不等于实际消耗。尚未进行付费模型的速度、费用和分类质量对照测试。

## 0.1.4：PR 自动快速预检

全局与当前仓库策略均提供独立 `autoPreflight` 开关，默认关闭；旧仓库策略未设置时继承全局。Issue 和 PR 的自动队列共享批量/并发预算，失败同版本不自动重试。PR 按事项更新、head/base 版本复用持久化预检任务，重启不重复调用。纯 CI 状态变化未反映在 GitHub 事项版本时，不保证自动重新预检；正式审查仍读取实时证据。

预检不获取 diff 和行内评论，不读取源代码，不自动运行完整审查、修改代码或发布。输入保留 PR head/base、草稿状态、检查结论和审查决定，每组至多 30 条；读取失败显式标识 unknown。与 Issue 分诊共用快速输出预算（默认 1800 token），模型和推理配置继承 Harness。手动预检同样使用这一轻量路径。
