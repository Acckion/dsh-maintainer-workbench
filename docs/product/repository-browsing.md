# PR / Issue 原始内容与审查视图

点击维护收件箱中的标题进入完整详情；右侧快捷预览的书本按钮也可打开。关闭或按 Esc 返回列表，保留选择和筛选。

- Summary：实时 GitHub 正文（支持 GFM）、状态、标签、负责人；PR 显示来源/目标分支与变更规模。
- Activity：GitHub 事件、讨论、审查以及逐行评论，保留原始记录链接、文件和行号。按需分页。
- Files changed：PR 原始 patch，按文件展开；标明二进制、缺失 patch、可能截断和 GitHub 3000 文件上限。
- Commits：提交消息、作者、时间、SHA 与原始链接。GitHub PR 提交接口最多提供 250 条。
- Checks：check-runs 与 commit statuses，未读取或无记录不视为成功；保留日志链接并支持分页。
- Agent：已有分诊、调查、实施、审查与验证流程。GitHub 原始记录与本地 Agent 产物分别呈现。

各页签懒加载，刷新会清空详情缓存。切换事项时取消旧界面请求。代码、提交和检查在读取前后核对 head/base；分页时不得混合不同 HEAD。详情接口只读，不启动模型、创建任务或发布 GitHub 内容。

无 GitHub 对应记录时仍可查看本地正文和 Agent 流程。原始 HTML 不执行，远程图片不自动加载，链接需用户点击打开。

本轮实现为原始内容浏览与现有 Agent 审查入口；未新增自由输入的 GitHub 评论发布器、原生 GitHub review 提交表单或合并按钮。检查视图不推断分支保护和最终合并资格。


## 工作台布局（2026-10-08）

全局页面使用顶部导航页签。收件箱、任务和待审核页面采用左侧列表、右侧详情布局，两侧独立滚动。选择事项直接打开内嵌 GitHub 详情；选择任务默认打开 Agent 页签，完整保留报告、证据、差异、执行记录及原有审核和发布控制。关闭详情保留搜索条件。

列表初次显示 50 项，可逐批加载；“选择当前列表”只选择已加载的筛选记录，不会暗中选中尚未显示的记录。仅浏览与切换页面不派发 Agent。窄窗口将列表和详情上下排列。移除宣传标语、装饰页脚和占据队列主区域的统计卡片，保留事实状态、权限和错误信息。

## Issue / PR 分类与组合筛选（2026-10-19）

- 事项类型（Issue/PR）与内容类型独立：Bug、Feature、Docs、Question、Maintenance 描述事项目的；P0–P3 描述影响和紧迫程度，不代表 Review 发现严重等级。类型以已有维护计划的人工分类优先；其次识别明确且唯一的 GitHub 类型标签（bug、feature/enhancement、docs/documentation、question、maintenance），再使用有效分诊/预检结果。明确的 P0–P3 或 priority:P0–P3 GitHub 标签优先于 AI 优先级；多个冲突的远端优先级按尚未评估处理，不自行选一个。
- Issue 分诊和 PR 元数据预检一次生成类型、优先级和少量建议标签，不另发模型请求。建议标签优先复用可见的仓库标签名称；资料不足在覆盖范围中说明，禁止凭 CI 权限不足或草稿状态提升优先级。
- 分类单独保存在 SQLite 中的事项记录，保留来源任务、输入指纹和时间。后续调查、实施、验证、Review 不覆盖分类。同步保留分类，快照按当前源数据标记是否过期；关闭、合并或只有时间戳变化不会使内容分类失效，标题、正文、标签、讨论数量或代码版本变化会失效。重启不重新分类，已有任务复用机制继续生效。
- PR 旧预检未包含分类时显示“尚未分类/尚未评估”，不将兼容报告里的默认 Maintenance/P2 当作模型评估。Issue 旧分诊按已有版本校验展示。
- 开关状态、内容类型、优先级、分析状态和多标签可以组合；标签支持“全部包含”和“任一包含”，忽略大小写。排序支持最近更新、优先级、编号；未知优先级排在最后。搜索同时覆盖标题、编号、作者、有效标签。
- GitHub 标签与本地建议分别显示，建议使用虚线和“建议”前缀。分类与筛选不修改 GitHub，不增加模型请求；发布标签仍走原有审核及预览。
- 过期结果保留历史，可用“分类已过期”筛选；旧优先级和旧建议标签不作为有效筛选条件。GitHub 原有标签仍可筛选。
- 回归：`tests/inbox-filters.test.ts` 覆盖组合筛选、任一/全部标签、来源去重、过期、排序和 PR 分类重启/同步保留；`scripts/browser-inbox-filters-fixture.mjs` 使用隔离合成数据检查宽窄布局与实际控件操作，不调用模型或真实 GitHub。
