# 类型化事项、补充信息与版本复核

日期：2026-10-04。开发起点：`d8c527d`，分支：`codex/issue-review-evidence`。

## 补充信息

Issue 详情可记录已提出的问题、等待回复的 GitHub 用户名及实际提问时间。记录是维护者的本地说明，不会自动发送评论；先使用现有发布预览或在 GitHub 提问，再保存记录。相同用户的活跃追问会去除重复问题，全部重复时复用原记录。问题和处理历史持久保存在原 SQLite 数据中。

同步仓库时读取等待用户在提问时间之后创建的评论。出现新回复进入“待重新评估”，不会自动判断信息充分或启动付费模型。其他用户的评论、提问之前的评论及旧评论编辑不会被当作该用户的新回复。权限失败保留等待记录并显示错误；首次读取和失败读取可以在下次同步重试。当前每次最多读取 100 条更新评论，达到上限显示部分覆盖。

维护者检查回复后选择“信息已足够”或“结束追问”，再重新分诊或继续调查。等待期间禁止重复快速分诊；自动分诊也跳过等待和待核对回复的事项。保存计划和同步不会清除追问历史。

## 各类型的短路径

- 缺陷：保存目标、复现步骤、预期与实际行为，以及验收条件。已配置计划但复现信息不足时，实施被阻止，仍可调查。
- 功能请求：先决定是否接受目标、范围和验收条件，再实施。已有功能分类但没有计划时也要求补齐取舍。
- 文档：保存文档位置、范围和验收条件后，主动作直接进入文档维护。
- 使用提问：生成或填写答复，记录答复或已发布链接后结束本地处理；不会自动关闭 GitHub Issue。需要代码改动时显式转换类型。
- 维护任务：按目标、范围与验收条件实施。

新计划进入版本键，目标或验收条件变化会使旧产物失效。既有无计划记录保持可读，历史缺陷流程不强制迁移。模型收到结构化计划和受限追问摘要；摘要有裁剪说明，不能把遗漏的信息当作不存在。

## 审查发现与 GitHub 讨论串

当前发现可批量记录接受、需要证据、不适用或已解决。批次先校验全部 ID，避免部分更新。后续审查通过精确的来源任务 ID 和发现 ID 引用历史问题，记录“已修复／仍存在／无法验证”及当前证据。最近一次交接审查中遗漏的发现默认无法验证，不能因为新报告没提到就认定修复。维护者修改复核结论后需要重新接受审查。

PR 审查可以只读同步 GitHub 讨论串的解决、过期及当前身份权限状态，显式关联本地发现。不会根据标题或行号自动关联，也不会因本地标记已解决而自动改变 GitHub。远端解决或重新打开必须先预览，再确认；服务端重新核对 PR head/base、线程所属 PR、当前权限及本地审查内容。认证完成后的实际请求发出前再次核对本地绑定。重复确认已达到的状态不会再发 mutation。

最多读取前 100 个讨论串；权限错误不会表示成空列表。远端最终版本查询和 GraphQL mutation 之间仍非原子事务，不能承诺消除全部远端竞态。接口依据 [GitHub GraphQL Pull requests 文档](https://docs.github.com/en/graphql/reference/pulls)。

## 真实工具执行证据

原生执行器观察 Harness 的 `tools/result` 最终结构化执行值和 Session 事件，不改变工具或审批机制。保存调用 ID、工具、命令、工作目录、记录的执行基线、实际退出码、信号、输出摘要及原始工具事件；只读验证、审查和 CI 还记录开始执行时的补丁指纹。嵌套 PTC 工具结果也有独立记录。取消和格式整理失败时保留已有记录。

测试报告只关联同基线、同补丁且命令完全一致的唯一调用；重复执行需显式 executionId，不挑选最后一次通过结果。报告声称 passed 而关联宿主执行失败时，权威阶段产物和兼容结果都改为 failed，保留模型原文供核对。不会把整个工具调用成功自动当作测试断言全部通过，也不会把 not_run 改为 passed。

没有结构化退出码时显示未知，不从 stdout 中解析可伪造的退出标记。实施任务中的工具记录不保证每条命令的执行时补丁一致，界面明确提示核对原生会话。复合脚本内部的子命令不会被拆成伪造的独立调用。历史任务没有这些记录时继续显示未关联。

界面摘要最多 6000 字符；每个原始事件保存上限 100 万字符，均标明裁剪。宿主自身已裁剪或写入外部 spill 文件的输出不会被宣称完整。日志文件权限 0600，读取接口按任务中实际存在的记录 ID 定位，不接受文件路径。
