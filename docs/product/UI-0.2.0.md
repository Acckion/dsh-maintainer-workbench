# Maintainer 0.2.0 界面与处理目标

仓库主导航为 Issues & PRs、Repository、Tasks。仓库设置与同步在导航右侧，全局设置在右上角。

事项默认打开 Assistant，展示当前结果、运行状态与可执行的下一步。Summary 保留原始正文；Changes 展示 PR 差异、提交与检查；Activity 展示 GitHub 讨论和活动。原 Triage、Execution、Review 深链接映射到 Assistant。切换页签不会调用模型。

Tasks 默认显示需要确认的结果；可筛选运行、完成、失败和全部。快速分诊与预检默认隐藏，可在显示选项中打开。只有明确的来源链或同一 goalId 才合并成一个条目，独立操作不合并；原始步骤仍可以追溯。

Assistant 的“调查并修复”“开始修复”“确认并实现”“检查并更新”保存显式处理目标。调查结束时如果尚未接受目标、范围和验收条件，暂停并等待确认。已确认的实施产物自动进入验证，验证报告完整通过才进入独立审查。失败、取消、输入变化或证据不足不自动重试；审查完成暂停等待维护者确认。此流程不自动接受产物、推送代码、发布评论或创建 PR。

目标、来源和暂停原因保存在现有 SQLite 任务记录中。重启按持久化记录恢复；只有新启动或明确复用为处理目标的任务会继续，历史任务不会自动增加模型调用。服务器端仍校验交接版本、计划范围和发布证据。

Repository 以仓库作为主区，左侧按缺陷、功能、文档、提问、一般维护、文档与仓库结构、开发指引、CI 分类建立子区。同一类别的 PR、Issue、执行阶段和重试记录按时间归入子区，显示来源、结论、事实、待验证假设、证据与后续步骤；较早记录可以继续加载。原始输出和工具日志通过对应任务打开。文档、仓库结构、开发指引和 CI 子区保留整理操作。

宿主侧复用仓库工作区，每个类别只有一个稳定的对话入口。类别记录以 recall 来源追加，不调用模型；重启从持久化日志恢复并按任务及内容指纹去重。执行会话仍绑定真实隔离工作副本以保留工具、审批和证据，结束后归档。旧任务工作区只移除已完成且完全由任务拥有的注册；共享会话、仓库目录、工作副本和日志保留。

## 版本与回滚

改造前标签：`ui-before-assistant-20261009`，提交 `4dfaba9`。本轮开发分支：`ui/unified-assistant-20261009`。0.2.0 通过验证后才安装，原插件文件和 SQLite 配置保持备份。

回滚界面请切换到上述标签后重新构建、安装；恢复旧程序不会删除原始任务数据。回滚后新版本的自动阶段衔接不再运行，已排队的独立任务仍需在任务页面检查。

## 验证范围

单元与集成检查覆盖来源链分组、后续失败不被旧通过遮蔽、SQLite 重启恢复、自动验证/审查衔接、失败停止与不重复派发。浏览器验证覆盖桌面和手机宽度下的需求确认、追问、审查发现处置、讨论串发布预览与执行证据。本轮使用合成仓库与确定性执行器，不以此宣称真实模型修复质量已验证。

2026-10-09 本轮检查：245 项测试全部通过，类型检查与构建通过。桌面 1440px 和窄屏 390px 的维护浏览器流程、返回焦点与滚动恢复、跨仓库派发、异步审查响应、关闭/返回详情、慢轮询均通过。浏览器验证使用合成资料及本地模拟执行器，没有调用付费模型或发布用户仓库内容。

0.2.1 安装修复：整理旧 profile 的任务工作区时，仅在历史数据库已经存在本地数据块时读取；未下载的云端占位文件跳过，不触发同步下载，也不阻塞 Harness 启动。原数据库和历史工作区不删除。
