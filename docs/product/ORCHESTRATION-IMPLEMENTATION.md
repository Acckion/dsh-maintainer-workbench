# 事项工作流编排实现记录

日期：2026-10-09。设计与验收依据为 [工作流编排计划](WORKFLOW-ORCHESTRATION-PLAN.md)。

## 已接入的流程

分诊、PR 预检和调查报告现在可以返回带来源的计划草稿。草稿包含目标、范围、验收、类型专属字段、推荐路线与缺口。历史报告缺少草稿时先重新整理材料；未生成完整信息的报告保留缺口，不自动编造验收条件。

维护者确认后，事项保存计划版本、输入身份、执行授权、步骤预算与检查点。代码或文档实施产生补丁后自动进入独立验证；必需验证通过后进入独立补丁审查，最后等待维护者审核。调查完成后提供更新草稿供核对。验证失败按类型给出恢复建议，不自动修代码或修文档；审查发现不自动触发修改。

编排调用现有队列、阶段产物、工作区、补丁交接和证据检查。重复确认复用进行中的授权；输入或已确认计划变化阻止继续。取消停止后续自动推进并保留产物，暂停允许当前任务结束。进程中断的执行保持失败，必须检查现场后明确重试；完成产物到下一步骤的检查点可以恢复，不静默重放状态不明的修改。

PR 审查意见经预览确认发布后，可等待作者新提交。新 head 触发重新预检和审查，保留历史发现供复核；相同 head 不重复派发。已有预检与计划足够时，仓库可开启只读自动审查，默认关闭，不自动修改或发布。原有创建草稿 PR、更新原 PR 和补丁导出继续使用各自的版本、证据与权限检查。

## 界面

- 详情默认显示系统建议、计划草稿或事项进度；草稿可直接确认或修改，来源和缺口可查看。
- 分诊、调查、实施和验证等单独阶段收进高级操作，保留原有入口及门槛。
- 补充回复在主区域显示，核对后重新评估；等待外部和执行中状态不占用人工决策队列。
- 首页按待确认计划、需要补充或解除阻塞、待最终审核展示事项，并可直接定位详情。
- 执行列表按事项聚合，运行记录及来源关系保留在事项内。
- 批量入口先分析所选事项，展示逐项范围和验收，再按建议开始；新建、复用、跳过与失败逐项展示。
- 最终审核继续复用五部分概览及发布预览，不自动批准中间报告或执行远端发布。

## 第二轮文档事项试用

1. 打开此前第二轮 Issue #3，在 Triage 或概览中点击“开始处理”。历史分诊没有计划草稿时，系统会重新整理材料。
2. 核对生成的具体目标、修改范围、验收条件、来源与缺口。已有材料无需重抄；草稿不准确时使用“修改建议”。
3. 点击“确认并开始”。系统在隔离工作区实施，连续验证和审查；宿主审批仍按现有权限处理。
4. 正常路径结束后到 Review 查看最终审核。遇到文档错误、环境问题或缺证据时查看具体原因，选择对应恢复，原失败报告保留。
5. 审核并选择具体交付预览。接受本地产物与对外发布仍分别确认；本轮不会自动合并或关闭 Issue。

真实模型在原 Issue #3 上的计划准确性、完整执行和实际人工操作负担仍需这次用户试用验证。自动修复审查发现、全面求值远端合并规则及精确费用预算保留后续。既有运行记录的高级入口继续可用，不通过删除历史减少界面数量。
