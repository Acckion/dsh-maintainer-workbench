# 个人试用版的补充复核

日期：2026-10-02。基于 `007fc8d` 的独立分支修正两处已经复现的边界问题，没有增加新的产品模块。此前交付与原分支保持不变。

## 修正内容

1. **后续失败验证不能被旧通过记录遮住。** 从验证任务或审查任务继续派发验证时，统一摘要现在沿明确交接关系寻找同补丁报告。每一层都核对事项、仓库、版本、基线、PR 目标、补丁和任务状态；循环、缺失、旧版本或另一实施根的记录不混入。原审查引用的验证与后续报告仍分别标明，点击证据进入实际来源任务。该摘要只展示证据，不静默撤销维护者的本地决定。
2. **过期的发布预览不能继续发送旧结论。** 打开预览会只读核对当前输入和 GitHub 版本。确认时再次核对，异步查询后的新 POST 和代码推送前也检查；审批或内容变化后，旧预览不能复用。轮询发现旧版本时，已打开的预览显示失效并禁用确认。失败发布若已在远端留下同任务标记，可只读核对并补记回执；即使输入后来变旧也不会重复发送。如果标记消失，过期输入仍被拒绝。

## 仍需亲自试用

- 云浏览器此前拒绝本地页面，本轮没有重试、绕过或真实浏览器视觉验收。按钮状态与回调由组件及 API 测试验证；真实导航、响应式布局与人类理解时间未知
- 普通 PR 的「预检 → 审查」如果没有本地实施补丁，摘要可能显示过于保守的来源链不匹配提示。这是已知的展示问题，本轮未修改；PR head/base 与原生证据仍需核对
- 真实模型正确率、修复成功率、Token、费用与维护效率没有测量。确定性模型夹具只证明工具链和维护阶段能够接通
- GitHub 的版本查询与评论写入不是跨请求原子事务。新的核验缩小过期窗口，不能宣称消除远端在最终查询后瞬间变化的可能

当前适合受控个人试用。先使用有权限、可丢弃的测试仓库；仍须单独接受本地产物并确认具体发布。不会自动合并、推送当前开发分支、发布 npm 或提交参赛材料。
