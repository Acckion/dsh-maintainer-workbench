# 通用验收方案

XiaomiNote-for-Mac（https://github.com/Acckion/XiaomiNote-for-Mac）由用户指定为后续验收样本，仅记录在本文件。产品源码、默认配置和任务工作流不得针对它特化。本轮只读取公开仓库资料，没有发布评论、标签或 PR。

## 样本覆盖

- TypeScript / JavaScript：package.json scripts、workspace/monorepo、测试与 lint。
- Python：pyproject.toml、包目录、测试、平台依赖。
- Rust：Cargo.toml、crate/workspace、测试入口。
- Swift/macOS：Package.swift / Xcode 项目、平台依赖、实际 CI 命令。
- 混合语言或未知结构：保留证据与未知，不凭仓库名称生成命令。

自动测试使用临时自建仓库验证结构识别、固定提交、符号链接处理、只读收集、自动 clone/worktree 隔离；它们不代表模型修复成功率。

## XiaomiNote 后续实例（不是产品规则）

2026-09-22 读取的公开 AGENTS.md 描述 Swift/AppKit/SwiftUI 项目。build.yml 声明 SwiftLint、MiNoteMac scheme 的 Debug build，以及 MiNoteLibrary scheme 的 xcodebuild test。验收时必须重新读取目标提交的文件，不能将这些命令作为全局默认值。

## 真实模型验收

### 原生代码审查的工具与证据门槛

证据页及任务 JSON 保存工具诊断：Agent 作用域内挂载的工具名、实际模型请求携带的工具名、调用数、Session 结果数、宿主执行结果数和错误数。仅保存名称与计数，不复制请求正文或凭据。这些观测用于区分未挂载、请求未带工具、模型未调用、调用结果未记录；不凭空把零记录归因于模型。

每个发现必须引用本任务的工具调用 ID 或 Session 结果 ID，并提供文件、真实行号、源码原文，以及具体输入、预期与实际行为。覆盖范围也需要源码引用，即使结论是无发现。引用必须关联同 Session、同 checkout SHA、同补丁摘要与工作区的成功读取，工作区内的绝对路径与相对路径按同一文件核验；工作区外路径、路径穿越及文件符号链接不接受。原文须同时出现在源码对应行和记录输出中。覆盖范围由已核验引用生成，模型原有覆盖声明保留在原始输出中。静态推演标记为 `reasoned`；声称 `executed` 必须另有关联的进程退出记录、精确命令和记录输出引用，失败的回归测试同样可以是有效执行证据。

缺少或不匹配的证据会把报告降为 `incomplete` 并列出阻塞，原始输出保留。原生审查在生成、批准、发布预览/发布和实施交接时检查门槛；历史原生任务缺诊断须重新派发。默认原生审查提示要求本 Session 直接读取适用 AGENTS.md、变更源码与相关测试；技能加载或其他审查报告不能替代源码读取。传给审查模型的历史交接只保留标为 historical_unverified 的发现摘要、追踪 ID 与维护者反馈，移除旧执行引用和覆盖声明；完整历史任务仍保存在工作台。审查派发按固定版本差异发现现存代码文件及相邻 `.test`、`.spec`、`test_`、`_test` 约定测试，将其列入必读清单；缺少任何必读文件的当前读取引用会阻塞验收。此识别范围不代表完整依赖或测试覆盖分析。正常原生审查的首份结构化报告未达门槛时，在同一个 Session 反馈失败原因并最多补齐一次证据；仍失败则标为 incomplete。补齐遵守原有权限和任务超时，不更换模型，不自动批准或发布。格式整理仍保持无工具，不重复执行任务。实施阶段同样隔离旧报告的执行声明并突出主要交接目标；先在同 Session 执行实际实施（不要求 JSON），宿主检查真实差异后再单独请求结构化报告。执行阶段差异为空且没有权限拒绝时，最多补齐实施一次；报告阶段不再请求修改。无真实补丁仍不能交付，补齐不绕过权限拒绝。需证据或驳回仍可记录，未达门槛的发现不能标记接受/解决。独立单元夹具和无 Session 的独立模式不冒充原生证据验收结果。

该门槛验证证据可追溯性、源码位置与执行关联，不自动证明推演正确、测试充分或审查覆盖完整；这些仍需要维护者判断和对照评测。

同一模型、同一推理设置、同一提交、同一任务输入，对比基础工作流与改进工作流。至少覆盖分类、非重复相似报告、可复现 bug、无法复现 bug、带缺陷 PR、无缺陷 PR、文档漂移。

记录：有效定位率、重复建议准确率、修复前失败/修复后通过的证据、无关修改、人工操作次数、耗时、Token、输出是否可直接审核。盲评结果并保留失败样本；不只展示成功案例。夹具仅用于工程链路验证；单个真实模型受控样本也不能据此声称智能水平或修复成功率提高。

验证阶段只传入主要补丁来源的变更摘要、验收条件和候选命令；历史审查发现、阻塞、执行 ID、测试状态和覆盖声明不进入验证提示。先执行检查，再单独生成 validate 报告；仅有文件读取时同 Session 最多补齐一次测试执行，真实权限拒绝后不重试。原生验证的 passed/failed 需唯一关联本 Session、同提交、同补丁和同工作区的可判定进程记录，否则降为 not_run 并列入阻塞。原始失败报告保留，历史记录不自动变为通过。
验证工具范围仅为本地读取、搜索、shell 与进程查看/终止；移除技能加载、编辑、工作流与委派入口，并通过单调工具 guard 拦截已识别的包安装命令。该 guard 不替代宿主沙箱或完整 shell 安全分析。阶段间使用宿主 `whenIdle()` 等待 driver 完成，而非仅等待 `turn/end`，防止后续报告请求停滞。没有本次可判定进程记录时，权威验证摘要标为未执行，环境阻塞声明标为模型未证实，原始输出保留；不据此建议提高权限。

验证按任务指定范围验收：范围内的必需检查缺失才是阻塞，未请求的整仓库测试保留为覆盖限制，小探针不能替代指定的 Vitest 文件。来源补丁的审查按其固定 checkout 差异发现必读源文件与相邻测试，即使补丁恢复后恰好与 PR base 一致也不能跳过读取；没有来源变更时仍按 PR 差异检查。

### 文档任务上下文预算

文档维护只挂载 read/glob/grep/edit/write/bash 和进程结果工具；不挂载技能、委派或发布工具。直接任务请求不附带其他事项，历史交接仅保留指定来源，远端背景限制为8000字符；目标文档和完整适用规则仍按需读取。
每次本任务 LLM 请求记录消息、工具定义、单独系统提示及各消息角色的字符数，不保存请求正文。token预算为字符数/2的保守估算，并非服务商精确tokenizer；已观察到32K限制的 openrouter/deepseek/deepseek-chat 路由在估算输入加输出预留超过30000时本地阻塞。此保护不会删除系统规则或重写工具证据，其他路由只记录诊断不套用32K限制。长文件应分段读取，必要内容超预算仍会阻塞。需真实第三条文档任务复测确认，自动测试不证明已消除全部真实请求超限。

文档任务遇到本地上下文预算阻塞时，通过宿主 agent/request-error 恢复接口先调用 toolResultPruner 的 durable prune，再在无裁剪进展时调用 compaction/context-overflow。原始工具结果留在 Session 日志，宿主创建显式替代节点并保持工具配对；预算保护不重写 request.messages。每任务最多3次有进展的恢复，无可缩减内容或宿主能力缺失则停止。摘要不等于新的工具执行，验收仍核对原始executionRecords。压缩器可能仍被真实路由上限阻塞，不承诺所有任务均可恢复。

预算阻塞必须返回标准 StreamChunk finish/error（WORKBENCH_CONTEXT_BUDGET），不能在 llm/stream waterfall 同步抛出；同步异常会绕过 agent/request-error，导致恢复机制不可达。导出诊断记录 no_progress/failed 及原因。真实任务日志已确认20K字符消息来自 agent-instructions baseline，不能作为无关历史删除。新增测试验证阻塞以可恢复流结束，不证明真实摘要模型已完成压缩。

预算估算只计入消息role/content/toolCallId/isError以及工具schema和独立system文本；Session来源说明、事件ID、缓存回放元数据不当作提示正文重复计费。依然是估算，不是供应商tokenizer；供应商专用隐藏开销可能不同。文档任务单次输出上限为min(仓库设置,3000)，为短执行状态及结构化文档报告预留空间；max-tokens仍按失败保留。恢复无进展时记录服务可用性、裁剪字符数、压缩结果和次数；不将服务缺失与无安全范围混淆。

本地 npm run harness 生成的开发overlay显式加载 tool-result-pruner 和 compaction-basic；tokenMeter复用宿主已有服务。pruner配置阈值3000、头1600、尾600字符；compaction沿用当前模型，auto=false，仅由工作台预算恢复触发，summary输出上限2048、headroom4096、retainTokens2000。不修改用户profile/凭据。host.contextServices暴露三个服务的实际存在状态。原生夹具检查服务加载和实际pruneContent长文本裁剪；此检查不是实际模型摘要完成证明。

实施报告只附带最多12条、约5000字符的证据索引，源码正文不再次嵌入；保留引用ID、路径、命令、退出码和短错误，完整记录在Session日志。文档阶段转入检查或报告时，若前一请求估算输入>=22000，在whenIdle边界调用宿主compactNow创建持久检查点，不新增写权限或重执行编辑。文档报告前有一次有上限的工具检查阶段，要求git diff --check及新增链接核验；提示不是成功证据，必须检查实际执行记录。原生夹具仅验证宿主接线，第三条真实任务仍需复测。

验证阶段也使用小仓库上下文、无其他事项、最高3000输出token、20行分段读取、预算恢复和报告索引；报告前在空闲边界按需建立检查点。文档来源的验证在未填写instructions时，由后端保存默认验收范围：真实diff检查、新增链接及标题核对、重复说明检查，未做安装运行明确限制。UI既有验收输入框注明随下一阶段派发，自定义内容优先；旧失败任务不可用新默认范围改写。

文档来源的验证从固定补丁的hunk和新增相对Markdown链接推导原生read/grep查阅范围；链接目标规划只读取仓库内真实路径、最大256KB文本，不把宿主规划算Agent工具证据。read最多20行、限制段落范围并拦截同offset/limit重复；glob不允许遍历。18次查阅后以DOCUMENT_INSPECTION_LIMIT流失败停止，保留未完成记录，不继续复读。提示要求先git diff HEAD及git diff --check HEAD（包含暂存修改）再定点核验。此范围控制不解析任意bash脚本，不是完整shell安全沙箱；宿主权限和版本/补丁证据仍负责验收。真实模型任务尚需复测。
文档验证必须实际执行 scripts/verify-document-patch.mjs，检查固定基线到当前补丁的空白错误、新增相对链接文件、标题锚点及完全重复文本。验收、接受和交付入口均要求同 Session、同版本、同补丁的成功原生执行记录及四项检查结果；仅 git diff/grep 或模型声称全部通过不能满足门槛。历史报告保留，重新验证生成新证据。完全重复文本检查不证明无语义重复，语义必要性仍需人工复审；此检查不证明安装或运行成功。

文档读取 guard 兼容原生 file_path 参数；超出允许段落时返回对应文件的 offset/limit 提示。文档验证首次执行提示明确给出检查器命令；报告前按指定命令是否存在执行记录判断是否补齐，不能用任意成功进程替代。缺少命令且没有真实权限拒绝时，同 Session 最多补执行一次；检查器执行失败保留失败，不重复重试或扩大权限。
